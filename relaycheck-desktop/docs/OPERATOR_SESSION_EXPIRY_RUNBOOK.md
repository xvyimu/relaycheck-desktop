# 签到会话过期处理手册（操作员）

**面向：** 日常运营 RelayCheck 的操作员
**日期：** 2026-07-12
**关联：** `docs/superpowers/specs/2026-07-11-session-relogin-plan.md`（#9 会话重登设计）· `docs/OPERATOR_RUNBOOK.md`
**一句话：** 上游站账号登录态会过期，签到就会失败。恢复靠**人工在浏览器里重新登录一次**，工具负责把这条路走顺——**它不会替你登录**。

---

## 1. 为什么会发生（先建立预期）

上游中转站的账号授权（Cookie / 浏览器 profile）**有有效期**。到期后：

- 签到任务会以 `auth_expired` 失败
- 账号 `login_status` 变成 `expired` / `manual_required`

这是站点侧的安全策略，**不是 bug，也无法用纯代码永久绕过**。工具能做的是：稳定地识别、清晰地提示、把重登步骤收成一条可重复的状态机。工具**不会**、也**不应**做的：自动填密码、绕过 2FA / 验证码、导出 TOTP。这些是硬边界。

---

## 2. 怎么识别（三个入口）

| 入口 | 看什么 |
|------|--------|
| **签到页** | 失败记录状态为 `auth_expired`（授权过期）/ `manual_required`（需手动） |
| **仪表盘 · 运营待办** | Action Center 会聚合「需要重新授权」条目，可深链到异常账号 |
| **站点与账号 · 全部账号** | 状态筛选选「异常账号」，异常卡片高亮，卡上会出现重登步骤条 |

**问题态集合**（异常判定依据）：

```text
登录态：expired | manual_required | captcha_required | two_factor_required
签到态：auth_expired | manual_required | failed
```

---

## 3. 恢复步骤（单账号，标准闭环）

异常账号卡片顶部会显示四步步骤条：

```text
① 打开网页登录 → ② 保存授权 → ③ 测试登录态 → ④ 签到/余额
```

按顺序操作：

1. **点「网页登录」** — 工具打开 Chrome 到该站登录页。
   - 卡片出现会话提示 chip：「登录窗口已打开 · 可保存授权」或「窗口已在运行 · 可保存授权」。
   - 若提示入口置信度偏低，先确认打开的确实是该站后台登录页；不对可在站点详情改登录 URL。
2. **在 Chrome 里手工完成登录** — 账号密码、2FA、验证码都在浏览器里做。**别过早关窗口。**
3. **回工具点「保存授权」** — 读取登录后的 Cookie 并加密入库；成功会提示保存了几个 Cookie，`login_status` 转 `valid`。
4. **点「测试登录态」** — 返回「登录态有效」即可；返回「已失效」说明登录没真正成功，回第 1 步重来。
5. **点「签到」/「刷新余额」** — 验证整条链路。

> 步骤条状态不落库，是本地 UI 相位（`idle` / `browser_open` / `auth_saved`）叠加服务端 `login_status` 推出来的。刷新页面后按当前 `login_status` 重新点亮。

---

## 4. 批量恢复（多账号）

「全部账号」视图的 **批量重登向导（BulkReloginWizard）**：

- 批量「打开网页登录」→ 逐个在浏览器完成 → 批量「保存授权」。
- 节奏仍是**人工逐个在 Chrome 内登录**，向导只做批量开窗与批量保存的编排。
- 2FA / 验证码账号仍需单独在浏览器内处理，无法批量跳过。

---

## 5. 常见失败与下一步

| 现象 | 含义 | 你的下一步 |
|------|------|-----------|
| 测态返回 `expired` | 登录没真正成功 | 重新「网页登录」，确认页面已登入后再「保存授权」 |
| 「保存失败 / 无 Cookie」 | 窗口没登入就点了保存，或关窗口太早 | 确认浏览器里已登录成功，别关窗口，再点保存 |
| 入口 `status=missing` | 没有已打开的会话就点了保存 | 先点「网页登录」 |
| 站点不可达 | Base URL 或代理问题 | 检查站点 Base URL / 本机代理 |
| 反复签到失败但不重登 | 误把 auth 失效当成签到重试 | 失败信息含「登录/授权/会话/401/403/过期」等即为 auth 类，走重登而非重试签到 |
| 2FA 账号 | 需二次验证 | 卡片内「2FA 指引」：在浏览器完成验证 → 回工具保存授权。**工具不代做验证。** |

---

## 6. 什么情况纯代码解决不了（务必人工介入）

以下**必须操作员亲自在浏览器里完成**，没有任何自动化替代：

- 首次或过期后的**账号密码登录**
- **2FA / 短信 / 邮箱验证码 / 人机验证（CAPTCHA）**
- 站点改版导致登录入口变化 → 需人工确认并更新站点登录 URL

工具的职责边界到「把你送到正确的登录页、并在你登录后把授权稳妥保存下来」为止。

---

## 7. 隐私与安全（操作员须知）

- **绝不**把 Cookie 原文、密码、Authorization、浏览器 profile 绝对路径贴进工单、截图、日志或对外材料。
- 工具默认脱敏；调试日志默认关闭。
- 会话数据本地加密存储，不外发。
