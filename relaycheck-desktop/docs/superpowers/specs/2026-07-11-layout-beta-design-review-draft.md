## 1. α 交付后基线（评审起点）

α 已具备、β 可复用的能力：

| 能力 | 现状 |
|------|------|
| 账号按站筛选 UI | 工具条站点 `select` + 筛选 banner |
| 服务端过滤 | `useSiteAccounts` → `?upstreamSiteId=` |
| 站点 → 账号跳转 | `NavigationIntent.upstreamSiteId` +「查看账号」 |
| 账号卡一级 CTA | 网页登录 / 签到 / 详情（≤3） |
| 侧栏分组 | 运营 / 资产 / 工具 |
| 仪表盘折叠 | collapsible cards + 默认收起 |
| 小屏侧栏 | `.sidebar` 桥接 ≤560 横向 chip nav |

**α 仍未解决的心智缺口（β 要回答的问题）：**

- 「站」与「号」仍是 **两个 Tab、两次定位**；选站只是账号页上的 filter，不是对象树。  
- 多站运维时：左脑记站点列表、右脑记账号列表，工作记忆切换成本仍在。  
- 规模（设计文档基线）：上游站 ~59、账号 25、多账号站常见 2–3 条——已满足 plan §8 规模门槛的一半；**运营心智是否「先站后号」仍依赖 §6 指标一周反馈**。

## 3. 问题陈述（β 要消灭的）

| ID | 问题 | α 之后是否仍在 | 影响 |
|----|------|----------------|------|
| B1 | 站点列表与账号列表空间分离 | 是 | 按站处理需 Tab 跳转或依赖 select |
| B2 | 「全部账号」与「某站账号」信息架构平级 | 是 | 心智无主键 |
| B3 | 大屏浪费：左栏无站点上下文时全宽账号网格 | 部分缓解 | 多站扫视成本 |
| B4 | 小屏若硬双栏会挤压 | α 未引入双栏 | β 必须两态，不可只做 ≥1180 |

**成功定义（可测，不主观）：**

- 大屏：一次点击选中站点后，右侧账号列表条数 = `GET /api/accounts?upstreamSiteId=` 条数。  
- 小屏：站点全宽 → 点入账号子视图 → 返回站点列表，无横溢。  
- 从仪表盘 Action Center 带 `upstreamSiteId` 进入时，右栏（或子视图）直接选中该站。  
- 不删除「全部账号」能力（可降级为次入口或顶栏开关）。

## 4. 方案形状（延续 design §3.2，细化）

### 4.1 大屏（≥1180）主从

```text
[Sidebar 三组] │ Topbar: 站点与账号（文案可选）
               │ ┌──────────────┬────────────────────────────┐
               │ │ 左 ~32%      │ 右 ~68%                      │
               │ │ 站点列表     │ 选中站账号列表                │
               │ │ 搜索+健康筛  │ useSiteAccounts(siteId)      │
               │ │ 选中 inset 3px│ 未选：空态「选择左侧站点」   │
               │ │ health+count │ 复用 AccountCard 一级 3 CTA  │
               │ └──────────────┴────────────────────────────┘
```

| 参数 | 建议值 | 备注 |
|------|--------|------|
| 左栏 min-width | 280px | 站名 + health + accountCount |
| 右栏 | `min-width:0` + flex/grid | 防横溢（设计系统强制） |
| 选中指示 | `inset 3px 0 0 var(--primary)` | 与侧栏 active 一致 |
| 数据 | 左：现有 sites 列表；右：仅 `?upstreamSiteId=` | 禁止右栏再拉全量 accounts 后客户端硬筛（α-B2 已证明服务端路径） |
| 空态 | 未选站 | 引导点选；不默认选中第一项（避免误操作规模大站） |

### 4.2 中屏 / 小屏（≤900）单栏栈

```text
状态 A：站点全宽列表（含「查看账号」）
状态 B：账号子视图（顶栏返回 + 当前站名 + 账号列表）
```

- 不在 ≤900 强制双栏。  
- URL/intent：仍用内存 `NavigationIntent`（无路由库）；子视图由 `selectedSiteId` state 驱动。  
- 390：沿用 α 无横溢约束；子视图工具条可折行。

### 4.3 IA 选项（评审必选其一）

| 选项 | 内容 | 破坏性 | 建议 |
|------|------|--------|------|
| **IA-1 不合并 Tab** | 保留「站点」「账号」两 Tab；β 壳只挂在「站点」页内（左站右号）；「账号」仍是全量+筛选 | 低 | **默认推荐** |
| **IA-2 文案合并** | 侧栏「站点」改「站点与账号」；账号 Tab 降为「全部账号」或折叠进工具组 | 中 | 需习惯成本评估 |
| **IA-3 物理合并** | 删除独立账号 Tab，全部进主从 | 高 | **不建议首期** |

**本草稿推荐：IA-1。** 先验证主从空间价值，再谈 Tab 合并。

### 4.4 组件边界（设计层，非实现）

| 组件（拟） | 职责 | 复用 |
|------------|------|------|
| `SiteAccountMasterDetail` | 布局壳、断点切换、选中态 | 新 |
| 左：`SiteListPane` | 从 SitesPanel 抽列表/筛选/卡片摘要 | 抽取 SitesPanel 子集 |
| 右：`SiteAccountsPane` | 工具条精简 + AccountCard 网格 | AccountsPanel 子集 + `useSiteAccounts` |
| 空态 / 错误 | 未选站、加载中、API 失败 | 现有 note/error 模式 |

**明确不新建：** 第二套账号卡、第二套过滤 API、新路由库。

## 7. 风险与回退

| 风险 | 缓解 | 回退 |
|------|------|------|
| 双栏实现复杂、CSS 层冲突 | 新 class 前缀 `master-detail-*`；不删 α 工具条路径 | 隐藏壳，站点页回 α 列表 |
| 用户仍要「全部账号」总表 | IA-1 保留账号 Tab | — |
| 未选站空态被嫌弃 | 记忆上次选中 siteId（localStorage，非密钥） | 默认不记忆 |
| 与 Sites 详情抽屉叠床架屋 | 左栏点选 ≠ 打开抽屉；详情仍二次点击 | 保持现抽屉 |
| 过早合并 Tab | 默认 IA-1 | 禁止 S7 含 IA-3 |
